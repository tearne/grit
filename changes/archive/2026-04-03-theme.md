# Theme

## Intent

Grit's UI colours are hardcoded and bear no relationship to each other — the palette is accidental rather than designed. Introduce a theme system with the autumn theme from the Helix editor as the first named option, selectable via `.grit.toml`. This gives the interface a warm, cohesive palette and opens the door to further themes without requiring any code changes.

## Approach

A new `theme.rs` module holds a `Theme` struct whose fields are the ratatui `Style` and `Color` values needed by the render functions. Two themes are shipped: `"default"` (the existing implicit palette, so current users see no change) and `"autumn"` (the Helix autumn palette).

**Helix autumn palette** (sourced from the upstream theme file):

| Name | Hex |
|---|---|
| black | `#212121` |
| gray3 | `#404040` |
| gray4 | `#646f69` |
| gray6 | `#a8a8a8` |
| white | `#F3F2CC` |
| brown | `#cfba8b` |
| green | `#99be70` |
| red | `#F05E48` |
| yellow | `#FAD566` |
| turquoise | `#86c1b9` |

**Theme struct fields** — one field per styled UI role:

```rust
pub(crate) struct Theme {
    pub(crate) title_bar: Style,
    pub(crate) list_highlight: Style,
    pub(crate) status_added: Style,
    pub(crate) status_deleted: Style,
    pub(crate) status_modified: Style,
    pub(crate) status_moved: Style,
    pub(crate) count_positive: Color,
    pub(crate) count_negative: Color,
    pub(crate) count_positive_bg: Color,   // applied at 1000+ magnitude
    pub(crate) count_negative_bg: Color,
    pub(crate) divider: Style,
    pub(crate) footer: Style,
    pub(crate) footer_notification: Style,
}
```

`count_style` in `tui.rs` keeps its magnitude logic; the theme supplies only the base fg colour and the heavy-bg colour for each sign.

**Config** — add `theme` as an optional string field in `Config`, defaulting to `"default"`. `Config::load` calls `Theme::from_name` to resolve it, returning an error for unknown names.

```toml
theme = "autumn"
```

**Autumn colour mapping:**

| Role | Field | Colours |
|---|---|---|
| Title bar | `title_bar` | bg `#404040`, fg `#F3F2CC` |
| List selection | `list_highlight` | bg `#404040`, fg `#F3F2CC`, bold |
| Added file | `status_added` | fg `#99be70` |
| Deleted file | `status_deleted` | fg `#F05E48` |
| Modified file | `status_modified` | fg `#FAD566` |
| Moved file | `status_moved` | fg `#86c1b9` |
| Addition count | `count_positive` / `count_positive_bg` | fg `#99be70`, bg `#2a3d1e` |
| Deletion count | `count_negative` / `count_negative_bg` | fg `#F05E48`, bg `#4a1810` |
| Divider | `divider` | fg `#646f69` |
| Footer | `footer` | bg `#212121`, fg `#a8a8a8` |
| Footer notification | `footer_notification` | bg `#212121`, fg `#FAD566` |

## Log

Mid-build: user requested (1) autumn as the default theme, (2) a key to cycle themes at runtime, and (3) reported that the background was still black in the autumn theme. Fixes: changed `default_theme()` in `config.rs` to return `"autumn"`; added `name: &'static str` field and `next()` method to `Theme`; added `t` as a cycle key in the TUI checklist loop; added `background: Color` to `Theme` (`Color::Reset` for default, `#212121` for autumn) and painted it over the full frame at the start of each draw closure.

## Conclusion

Delivered as planned, plus the mid-build additions (see Log). `count_style` was simplified — the `positive: bool` parameter and its internal branch were replaced with explicit `fg` and `heavy_bg` colour arguments, which the call sites supply directly from the theme. The `Theme::default_theme()` method is named `default_theme` rather than `default` to avoid conflicting with the `Default` trait. `Tui::run` takes the initial theme by value so the loop can replace it on `CycleTheme`; a `name: &'static str` field on `Theme` makes `next()` possible without a separate tracking variable.
